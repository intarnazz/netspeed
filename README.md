# netspeed: замер скорости скачивания

Консольный скрипт на Python. Делает **10 последовательных запросов** к адресу (например, к тяжёлой картинке), дожидаясь полного ответа на каждый, и считает:

- среднее время запроса;
- общий объём скачанных данных;
- скорость скачивания в **Мбит/с**.

Только стандартная библиотека, ничего устанавливать не нужно. Требуется Python 3.8+.

## Запуск

```bash
# адрес аргументом
python netspeed.py https://example.com/big-image.jpg

# без аргумента адрес будет запрошен интерактивно
python netspeed.py

# список адресов из файла (по одному в строке, # - комментарий)
python netspeed.py --file urls.txt
```

Если запустить скрипт без аргументов (например, двойным кликом), в конце он ждёт нажатия Enter, чтобы окно не закрылось сразу. Для остальных запусков то же включается флагом `--pause`.

Адрес и `--file` можно использовать вместе: сначала проверяется адрес из аргумента, затем адреса из файла. Пример списка лежит в `urls.txt`, замените его своими адресами.

## Что видно во время работы

В терминале два прогресс-бара, таймеры и счётчики, обновляются на месте:

```
Запросы   [████████████░░░░░░░░░░░░] 5/10  (успешно 5, ошибок 0)
Файл #6   [███████████████░░░░░░░░░]  62%  620.00 КБ / 1.00 МБ
Таймер    запрос 00:00.2  |  всего 00:01.4
Скорость     29.31 Мбит/с  |  Скачано всего: 5.62 МБ
```

- **Запросы**: от 0 до 10.
- **Файл**: от 0 до размера файла, на каждом запросе начинается заново. Если сервер не сообщил размер (нет `Content-Length`), показывается счётчик полученных байт.
- **Таймер**: время текущего запроса и общее время по адресу.
- Если вывод перенаправлен в файл или пайп (не терминал), бары отключаются и печатается по строке на запрос.

После 10 запросов выводится итог:

```
Итоги:
  Успешно: 9 из 10, не удалось: 1
  Среднее время запроса: 0.532 с
  Общий объём скачанных данных: 9.00 МБ
  Ошибки:
    запрос #4: HTTP 503 Service Unavailable
>> Скорость скачивания: 94.30 Мбит/с
```

Если адресов несколько, после каждого печатается его итог, а в конце общая сводка по всем.

## Единицы и формулы

| Величина | Как считается |
|---|---|
| **Скорость** | `общий объём × 8 / суммарное время / 1 000 000`, в **Мбит/с** (как в тарифах провайдеров) |
| Среднее время запроса | суммарное время успешных запросов / их количество |
| Объём | сумма байт тела ответа успешных запросов; в МБ, 1 МБ = 1 000 000 байт |

Время запроса измеряется `time.perf_counter()` от отправки запроса до полного получения тела ответа. В него входит установка соединения. При включённом сохранении файлов в него входит и запись на диск.

Среднее время, объём и скорость считаются **только по успешным запросам**. Байты, полученные до обрыва неудачного запроса, в объём не входят, но показываются отдельной строкой. Если успешных запросов нет, выводится `н/д`.

Чтобы замер был честным, скрипт шлёт `Cache-Control: no-cache` (CDN не должен отдавать из кэша) и `Accept-Encoding: identity` (считаем байты без сжатия). Редиректы разрешены (до 5).

## Ошибки

- **Неверный адрес.** Адрес должен начинаться с `http://` или `https://` и содержать хост. Иначе скрипт выводит причину.
- **Адрес недоступен.** Первый запрос служит и проверкой адреса. Если он не удался, выводится ошибка (с кодом `404`, `403`, `500` и т. д., если сервер ответил; для сетевых проблем с понятным текстом: DNS, отказ соединения, таймаут, SSL) и остальные запросы пропускаются.
- **Сбой посреди серии.** Если файл стал недоступен на одном из следующих запросов, серия продолжается, а в итоге указано, сколько из 10 удалось и какие запросы упали и почему. Повторных попыток нет.
- **Ctrl+C** прерывает работу и показывает промежуточный итог.

Коды возврата: `0` - все запросы по всем адресам успешны; `1` - были ошибки; `2` - ошибка использования (например, нет файла со списком); `130` - прервано пользователем.

## Настройки (`config.ini`)

| Ключ | По умолчанию | Описание |
|---|---|---|
| `logging_enabled` | `false` | сохранять ли логи в папку `logs/` |
| `max_logs` | `0` | сколько последних логов хранить; нужен `logging_enabled = true`; **`0` = ничего не хранить** |
| `download_files` | `false` | сохранять ли скачанные файлы в папку `downloads/` |
| `download_first_only` | `false` | сохранять только первый успешно скачанный файл каждого адреса (нужен `download_files = true`) |
| `timeout` | `30` | таймаут на соединение и на ожидание очередной порции данных, секунды |

Неверные значения (не `true`/`false`, отрицательное число, мусор), отсутствующие ключи, отсутствующий или битый файл заменяются значениями по умолчанию. Скрипт при этом печатает короткое предупреждение.

## Логи и скачанные файлы

Один запуск скрипта равен одному логу (даже если в списке много адресов). Когда число логов превышает `max_logs`, удаляются самые старые.

```
logs/
  .clean_logs.py                 <- очистка логов
  2026-11-17_14-30-05/run.log    <- лог запуска
downloads/
  .clean_downloads.py            <- очистка скачанных файлов
  2026-11-17_14-30-05/
    example.com/01_big-image.jpg ...
```

В `run.log` записаны настройки запуска, по каждому запросу статус, размер, время, скорость, ошибка и **сохранён ли файл (`saved=<путь>` или `saved=no`)**, а также итоги. Имя папки запуска совпадает в `logs/` и `downloads/`. Имя файла берётся из `Content-Disposition` или из адреса. Если сохраняются все файлы, к имени добавляется номер запроса.

В адресе могут быть токены доступа, а они попадают в лог. Не коммитьте и не пересылайте логи не глядя (папки `logs/` и `downloads/` уже в `.gitignore`).

## Очистка

Скрипты лежат внутри своих папок. Имена начинаются с точки, поэтому в списке они идут первыми.

```bash
python logs/.clean_logs.py              # спросит подтверждение
python logs/.clean_logs.py --yes        # без вопросов

python downloads/.clean_downloads.py
python downloads/.clean_downloads.py --yes
```

Каждый скрипт удаляет только то, что лежит рядом с ним (кроме файлов, начинающихся с точки, то есть самого скрипта). Логи и скачанные файлы чистятся отдельно.
